# Identity direction paper

## Communication job

Help developers understand within three seconds that many routine inputs can pass through one controlled local routing point and return as one clear typed result.

**Primary audience:** developers evaluating small local inference infrastructure.

**Primary message:** keep routine inference close.

**Reason to believe:** one typed contract, explicit provider identity, measured output, and a guarded local network boundary.

## Personality

Precise, calm, technical, accountable, and compact.

The identity must not feel futuristic, magical, anthropomorphic, military, crypto-related, or like a general-purpose AI assistant. Avoid glowing brains, sparkles, robots, gradient spheres, fake dashboards, and claims of intelligence.

## Symbol construction

Three incoming rails contract around an orange local node and leave as one rail. At small size it reads as a routing gate; at large size it reveals the controlled reduction and packet metaphor.

- Construction field: 96 × 96 units.
- Clear space: at least half the symbol height on all sides.
- Minimum digital size: 24 px; prefer 32 px or larger.
- Preserve geometry and colors. Do not rotate, skew, outline, add gradients, or place over busy imagery.

The symbol must remain meaningful without the wordmark: routing, locality, and controlled transformation are the recognizable behavior.

## Visual system

| Role | Value | Use |
|---|---|---|
| Ink | `#101B24` | primary background and text |
| Paper | `#F7F6F2` | warm light surface |
| Cool neutral | `#F3F5F6` | diagrams and secondary surfaces |
| Slate | `#52606A` | secondary text |
| Route blue | `#315C78` | paths and structural links |
| Signal orange | `#E56632` / `#F0783E` | local node and active state only |

Use a neutral system sans for prose and UI, and a system monospace for commands and structured output. The type hierarchy uses no more than three sizes in one composition and two weights in ordinary documentation.

Spacing follows an 8 px base rhythm. Corners are restrained: 12–22 px for large panels, 2–6 px for packet nodes. Shadows are unnecessary; hierarchy comes from contrast, spacing, and borders.

## Information hierarchy

1. One-line promise.
2. Implemented proof.
3. Trust and network boundary.
4. Quick start.
5. Contract details and roadmap.

Secondary qualifications remain visible but never compete with the primary promise.

## Motion direction

If motion is produced later, inputs move with uneven density toward the fixed local node, pause, then leave as a smaller aligned packet. Acceleration is precise, not elastic. The local node never pulses like a magical source; it behaves like infrastructure.

## Future icon direction

Use the dark symbol for repository and application icons. Test at 16, 24, 32, 64, 128, 256, 512, and 1024 px. Platform-specific corner masks and safe areas must come from the current official platform kit rather than being baked into the master symbol.

## Future App Store screenshots

If the Broker later becomes a distributable application, create screenshots only after a real interface exists. Each frame gets one outcome, one supporting proof, and large safe margins. Use official Figma platform resources for current device geometry; never fabricate an interface solely for store imagery.

## Future film storyboard placeholders

1. **Tension:** an oversized context stream approaches a local boundary.
2. **Decision:** the fixed node routes routine work locally.
3. **Proof:** provider, latency, and measured size appear as factual metadata.
4. **Resolution:** a smaller structured packet exits; the brand appears only afterward.

No production film should be made until measurements are captured with documented hardware, provider, model, input, and method.

## Brand-Off test

The system fails if replacing the name with another AI tool still feels correct. It passes only when the contraction geometry, fixed local node, restrained infrastructure tone, explicit measurements, and network-boundary language remain inseparable from the product’s job.
